# 安贞医联 · 医疗协同服务 v3.2.0

云端入口：**[打开安贞医联工作台](https://8.147.71.90/)**，本机关闭后云端仍可访问。服务器运行方式、共享数据与维护见 [Linux / 阿里云部署说明](docs/linux-deployment.md)；需要本地运行时按下文启动。

一个统一入口，连接 **下级转上级、上级转下级、患者导诊**。v3.2.0 在三模块基础上，增加病历与影像附件、院内诊疗信息导入、医务审核与退回重提、消息提醒、独立下转接收中心，以及含今天的可选工作时间与候选医生排序。完整变化见 [3.2.0 功能说明](docs/release-3.2.0.md)；本轮页面操作、数据保留与云端部署结果见 [3.2.0 验证记录](docs/verification-3.2.0.md)。

当前交付为可在云端或本地运行的功能框架。真实模型用于匹配、评分、问答、病历文字识别和异常摘要；在线工作台的上转记录、下转安排、连续监测与通知统一保存在应用服务器，访问同一服务的浏览器共享记录。医生资料与照片随应用部署，模拟照护数据由服务器初始化；排班及路线采用预置数据，尚未连接医院业务系统。云端入口已启用 HTTPS，HTTP 访问会自动跳转；目前使用公网 IP 访问。功能操作见 [三模块说明](docs/care-platform.md)，数据保存方式以下文及 [云端部署说明](docs/linux-deployment.md) 为准。

## 1. 启动与稳定运行

需要 **Node.js 22 或以上**，没有第三方运行依赖，无需 `npm install`。

1. 解压整个文件夹，使用文本编辑器打开 `.env`。macOS 可按 Command＋Shift＋句号显示隐藏文件。
2. 在 `MOONSHOT_API_KEY=` 后填写 Kimi 开放平台 API Key 并保存；不是 Kimi Code 订阅密钥。
3. **macOS**：双击 `启动工作台.command`，安装或更新当前用户的后台服务。成功后可以关闭终端；服务配置为登录后自动启动、进程退出后自动重启。
4. **Windows**：双击 `启动工作台.bat`，保留运行窗口。任意系统也可在此目录运行 `npm start`，该方式在前台运行，需保留终端。
5. 浏览器打开 **http://127.0.0.1:4173/**，在服务首页选择所需功能。

macOS 后台服务从 `~/Library/Application Support/AnzhenReferralWorkspace/` 中的运行副本启动，不依赖下载目录内的项目文件持续存在。业务记录另存在该目录下的 `var/`，更新代码不覆盖记录。**修改原项目代码或 `.env` 后，必须再次双击启动脚本，或在原项目目录运行 `npm run service:restart`，将改动同步至运行副本。** 单独刷新浏览器不会同步代码。

```sh
npm run service:install
npm run service:status
npm run service:restart
npm run service:stop
```

`service:stop` 会停止后台服务并暂停自动启动，直到再次运行安装或重启命令。本地网址只在本机可用；电脑睡眠或关机期间无法访问。自动启动配置不等于已完成重新登录验收。安装目录、日志与恢复方法见 [本地后台服务说明](docs/local-service.md)。

如 `.env` 不存在，先运行 `node scripts/setup.mjs`。启动脚本只补建缺失文件，不覆盖现有密钥。首次安装前关闭此前手动启动的工作台；安装程序不会停止占用端口的其他程序。建议保留 `PORT=4173`，便于继续使用原网址；直接运行 `npm start` 时数据默认保存在项目 `var/`，与 macOS 后台服务及云端服务器的数据各自独立。

```dotenv
MOONSHOT_API_KEY=在本地填入你的Key
KIMI_BASE_URL=https://api.moonshot.cn/v1
KIMI_MODEL=kimi-k3
KIMI_REASONING_EFFORT=low
KIMI_TIMEOUT_MS=90000
PORT=4173
```

国内开放平台地址为 `https://api.moonshot.cn/v1`；国际平台 Key 使用 `https://api.moonshot.ai/v1`，账户与权限必须对应。本程序只允许这两个官方 API 地址。模型配置仅在技术配置中出现，不向页面操作人员展示供应商品牌。

## 2. 三个服务入口

| 入口 | 主要使用者 | 主要操作 | 形成的结果 |
| --- | --- | --- | --- |
| 下级转上级 | 下级医院医生、医务审核人员、上级转诊中心 | 录入或导入病例及附件 → 匹配医生、选择意向时段 → 医务审核 → 通过后接收协调；退回则补充后重提 | 共享上转申请、审核历史、站内待办与协调记录；急症同步立即联系 |
| 上级转下级 | 上级出院团队、下级接诊团队 | 新建患者或导入资料 → 下转住院/康复/护理/随访服务 → 下转接收中心登记安排 → 连续监测 → 紧急事件整理与复核 | 可编辑的照护档案、独立接收队列、监测时间线、AI 摘要和处理记录 |
| 患者导诊 | 患者及陪诊人员 | 填写或识别病历 → 核对文字 → 推荐医生与诊室 → 查看出诊时间、路线与就诊问答 | 就诊方向、候选医生和到院指引；不会创建挂号或预约 |

首页与顶部通知入口显示待处理的紧急照护事件；“消息提醒”集中显示上转审核、退回补充和接诊待办。站内消息可标为已读并进入对应申请；短信、微信仅显示“未配置”，不会伪造发送结果。其他在线浏览器约每 5 秒检查共享记录更新。

**下级转上级**保留原有急性心梗、房颤和术后康复病例。病例改动后旧匹配失效，需重新匹配。支持附加 JPG、PNG、WebP、PDF 或 DICOM（.dcm）文件，每份不超过 5 MB、每单最多 10 份；上传成功后随申请供审核方和接收方查看。择期转诊直接选择详情表中的意向时段，提交后先进入“医务审核”。审核人核对病例和附件并填写意见，通过后进入“上转接收中心”，退回则补充资料后重新提交。急症联系与院内审核同步开展，不等待普通排班或页面审批。

**院内数据接入**提供东华、嘉和示例就诊入口，以及约定格式的 JSON 上传或粘贴导入。核对后可带入上转草稿或下转患者表单；当前未接通这些厂商的真实 HIS/EMR 接口，不会自动读取院内患者。导入字段与操作方法见 [三模块说明](docs/care-platform.md)。

**上级转下级**预置三位虚构患者与连续七日监测，也可新建患者或编辑既有患者信息，保留原监测和处理历史。可安排“住院延续治疗、心脏康复、术后护理、慢病随访”，提交后进入独立“下转接收中心”，按待接收、已安排或全部申请查看。接收人员复核交接内容并登记科室、床位或服务地点，随后回到同一患者的连续照护。新建患者初始没有监测值，不自动补造测量结果。紧急事件先保存原始情况，再请求 AI 整理；失败时保留告警和重试按钮，人工复核后登记处理。

**患者导诊**支持文字输入、PNG/JPG/WebP 图片识别及问答。图片本地处理后，在点击“识别病历”时发送；识别文字须核对并勾选确认，才能用于推荐。推荐医生详情展示共用工作时间表；路线为预置楼层与区域示意，需向院方核实。

所有 AI 生成均由用户操作触发。录入普通监测、切换视图、查看排班及打开首页不会自动调用模型；保存明确标记为紧急的事件会触发摘要整理。“重新整理摘要”、重新推荐和重试问题会产生新的模型调用。

## 3. 工作时间、匹配与 AI 处理

三个医生详情入口共用含今天的近 7 日工作时间表，可查看上午、下午及已过时段；上转择期详情可直接点击可选时段。候选医生支持“专业匹配优先”“最近接诊时间优先”“意向登记较少优先”，并可仅看近期可登记医生；急症不按普通排班排序等待。参考余量由规则生成，“已登记意向”来自本平台记录，不扣减或占用医院真实号源，也不证明医生在岗或挂号成功。

当前默认 `kimi-k3 + reasoning_effort: low`，K3 请求使用严格 JSON Schema。可手动配置 `kimi-k2.6` 的非思考模式和 JSON Mode；不会自动更换模型。官方出处和参数说明见 [API 文档摘记](docs/kimi-api-notes.md)。

上转与导诊使用同一医生匹配接口，每次最多返回 8 位候选，分项为专业方向 45 分、相关技术 30 分、转诊目的 15 分、资料充分性 10 分。模型通过 `evidenceRefs` 选择所选医生的简介、专长或门诊条目，服务端解析为真实资料原文，并校验医生 ID、照片、重复项、分值及总和。失败时提示重试，不以规则结果冒充 AI 结果。

学历、职称、虚拟排班和意向时段不参与评分。针对已覆盖的技术表述，公开资料缺少相应证据时限制技术项得分，并重新加总排序。这是有限的证据保护，不覆盖全部医学表达，不证明临床结论或疗效。

下转异常摘要整理已有监测变化、待补充信息和交接重点，时间按北京时区理解；不自动作出诊断、处方或接收决定。图片识别只提取资料，保留无法辨认的项目供人工核对。模型没有实时检索医院排班、床位或院内地图的能力。

## 4. 数据保存与接口边界

- 在线上转记录、下转服务安排、接收登记、监测与告警写入服务器持久目录；不同电脑访问同一个网址时读取同一份业务数据，页面约每 5 秒检查更新。
- 服务器已保存的既有记录及状态保留。原浏览器存储键 `anzhen-referral-demo-v1` 与 `anzhen-downward-workspace-v1` 用于兼容旧版记录；首次连上共享存储时执行一次性合并。3.2.0 新迁入且未经过本版审核流程的旧上转记录转为待审核，保留原接收信息与历史事件并增加迁入说明；不会绕过审核直接进入新接收流程。浏览器不能读取其他网址的存储，本地网址历史仍需单独迁移。
- 下转“上级/下级医院视图”是角色视图，均读取服务器共享档案。它们不代表已经连接两家医院的业务系统，也不构成账号权限管理。
- 转诊附件存入服务器私有持久目录 `DATA_DIR/attachments`，申请保存附件元数据和访问地址；不把大段图片内容写进业务快照。附件不会自动送给模型解读，也不等于正式电子病历或 PACS 归档。导诊识别用图片、识别文字、推荐与问答仍在当前页面内存，刷新可能清除。
- 本地 `.env` 或服务器私有配置仅由服务端读取，浏览器不接收 Key。导诊点击识别后，图片经应用服务端发往已配置的模型服务，该识别接口不将图片写入磁盘或日志；这与单独的持久化附件上传功能不同，也不等于承诺外部服务商的数据留存政策。云端配置位于 `/etc/anzhen-fde/app.env`，权限 `0600`，仅含应用设置和 API Key，不含 SSH 密码。
- 使用虚构或充分脱敏资料。AI 操作会将相关文本、医生资料、图片或监测数据发送至配置的外部服务。
- 安贞医生库来自已有整理资料，当前 54 位有照片医生可展示，资料日期为 2026-09-14。下转协作医院及医生为虚构预置资料，使用中性头像。
- 未连接真实 HIS/EMR、挂号、床位、设备监测、短信/微信或院内导航系统。站内消息是本平台待办，不代表院方或外部渠道已收悉。保存申请不等于确认接收、占号或占床。
- 云端数据位于 `/var/lib/anzhen-fde`，不在应用版本目录、Git 仓库或发布压缩包中；更新代码、重启服务和切换代码版本不会重置业务记录。访问者共用同一工作区，暂未分配独立账号或个人数据空间。
- 应用进程仅监听 `127.0.0.1`；云端由 Nginx 提供公网入口。当前没有人员账号、跨院权限或完整审计系统；部署上线不代表已具备真实院内生产使用条件。

## 6. 常见问题

- **云端网址打不开**：先检查服务器应用状态及宝塔 Nginx，按 [云端维护说明](docs/linux-deployment.md) 排查；云端服务不依赖本地电脑持续开机。
- **本地网址打不开**：macOS 先执行 `npm run service:status`，必要时再次双击启动脚本；Windows 或前台运行需保持窗口开启。查看 [后台服务说明](docs/local-service.md)。
- **修改后没变化**：macOS 运行 `npm run service:restart` 同步运行副本，再刷新浏览器；前台方式停止旧进程后重新启动。
- **端口被占用**：后台服务运行时不要同时执行 `npm start`。切回前台时先 `npm run service:stop`。
- **模型未配置或请求失败**：核对 `.env`、平台地址、账户权限及额度，然后同步并重启。`configured: true` 只代表已加载 Key。
- **401/403/429**：分别核对 Key、模型访问权限和账户额度/限速。自动重试不会发生；再次点击会发起新请求。
- **识别后不能推荐**：先核对识别文字并勾选确认；超过 5000 字时精简为病情摘要。上传图片支持 PNG/JPG/WebP，原图不超过 5 MB，前端压缩后的发送内容不超过 3 MB。
- **紧急摘要失败**：原始事件和待处理通知仍保留，可先人工联系团队并登记情况，再点击“重新整理摘要”。不要等待 AI 后才发起紧急联系。
- **换浏览器后没有记录**：先确认两边打开同一个服务网址，并等待同步完成。本机服务与云端是不同数据空间；旧版本浏览器记录需完成一次性导入，导入成功前保留原站点存储。
- **业务记录会随更新消失吗**：数据保存在独立持久目录，安装器不覆盖它。迁移服务器或删除磁盘前仍需单独备份；发布压缩包不包含业务记录。
