# 医疗协同服务 v3：三模块与操作边界

v3 的服务首页提供“下级转上级”“上级转下级”“患者导诊”三个入口。它们分别面向专科诊疗升级、诊疗后接续服务和患者就诊前准备，共用医生资料展示与近 7 日工作时间组件。

本文描述当前实现的功能框架。界面中的角色视图、工作时间、协作人员和院内路线不代表已经接入真实医院系统。当前服务可通过本机或云端网址运行；在线申请和照护数据统一保存在所访问的应用服务器，同一服务的多个浏览器共享记录。

## 1. 服务首页

首页提供三张功能卡，并显示已有上转申请、待协调申请、连续照护患者和紧急待处理数量。左侧导航可随时返回首页或切换模块；顶部照护通知可跳转到上级视图中的紧急事件。

首页统计来自当前服务器的共享记录，没有院方数据库汇总或跨医院账号范围的含义。上转和下转分别保存各自的业务内容，页面约每 5 秒检查更新；旧版浏览器存储键保留用于一次性历史导入。

## 2. 下级转上级

适用于下级医院需要上级专科进一步评估、复杂治疗或急症救治的场景。

1. 在“下级转上级”填写来源医院、发起医生、病情及转诊原因，也可选择已有虚构病例。
2. 点击“匹配接诊医生”，获取病例摘要、候选医生、100 分制匹配分和公开资料依据。
3. 查看医生简介、照片、专业信息与近 7 日工作时间。
4. 择期病例选择意向日期和上午/下午时段，进入复核后确认转诊。紧急病例进入“复核并立即对接”，不按普通门诊时间等待。
5. 在“上转接收中心”登记科室与床位或就诊地点；在“上转记录”回看。

匹配分由专业方向、相关技术、转诊目的和资料充分性构成，不是疗效、诊断概率、医生能力排名或院方接收概率。病例变动会使旧匹配失效，避免混用不同病例的结果。

转诊确认创建共享工作台中的申请；“已登记待核实”表示已有协调登记，不能解释为医院已收到或接受申请。系统不会实际挂号、锁床、发送院方消息或安排救护转运。

## 3. 上级转下级与连续照护

适用于患者已经完成上级医院主要诊疗，需要回到就近医院继续住院治疗、康复、护理或慢病随访的场景。重点是上级治疗计划与下级执行服务的衔接。

### 建立下转服务

上级视图先选择患者，再点击“发起下转申请”，填写服务类型、计划接收日期、意向医生、治疗目标及交接要求。下转服务包括：

- 住院延续治疗：登记接收科室、床位意向及治疗计划交接要求。
- 心脏康复：衔接康复评估、训练计划执行和过程随访。
- 术后护理：衔接日常护理、恢复情况观察与复诊计划。
- 慢病随访：衔接用药执行核对、症状和生命体征记录。

切换“下级医院视图”后，可查看同一申请，填写科室、床位或服务地点，以及后续监测安排。保存后，上级视图也能看到已登记的接收情况。更改下转计划后需重新核对接收安排。

接收团队为预置的虚构协作单位和医生，使用中性头像，与安贞医院公开医生照片库分开。资料和服务条件仍需核实；选择团队不代表已证明具备某项真实接诊能力。

### 共享按日期的监测记录

预置三位虚构患者，每位都有连续七日监测数据。页面展示最近血压、心率、血氧和体重，提供近期趋势图和按日期筛选的时间线。人员可以录入新的监测时间、体征及症状反馈。

两个角色视图读取同一份服务器记录，保存后均可查看。不同电脑或手机打开同一个服务网址，也会同步取得这些记录；本机运行服务与云端服务是两个独立数据空间。此共享机制尚未连接医院原有系统，也未按医院账号划分访问范围。

当前数据来自预置记录与人工录入，尚未连接床旁监护、可穿戴设备或院内监测接口。趋势图仅呈现输入值；没有宣称已完成监测异常阈值的临床验证。

### 紧急事件 → AI 整理 → 上级复核

1. 下级团队点击“记录突发情况”，或在监测录入中勾选紧急标记，填写实际观察值及事件说明。
2. 系统先保存原始事件，再显示“AI 正在整理”。紧急待处理计数立即更新，不因模型尚未返回而丢失事件。
3. AI 根据近期记录和事件说明，整理摘要、关键变化、待补充信息和交接重点。服务端将事件与记录时间按北京时区统一理解。
4. 上级视图显示醒目的紧急通知。整理完成后优先阅读摘要，原始情况可展开核对。
5. 上级人员填写处理与联系记录，人工复核后点击“确认并登记处理”。两个视图均能看到处理结果，紧急待处理数减少。

AI 不代替紧急联系，不生成已执行救治的虚假回执，也不自动给出处方或接收决定。紧急联系应同步进行，不能等摘要完成才处理。

整理失败时，原始事件、待处理状态和“重新整理摘要”入口保留；刷新后中断的整理也可重试。已有摘要但尚未处理时，可以对同一事件重新整理，不会新增一条告警。每次重试都会产生新的模型调用。

“已登记处理”表示人员保存了处理说明，不表示系统已经向真实院方发送通知或确认对方收到。当前通知是应用页面内提示，没有短信、电话、院内消息或推送通道。

## 4. 患者导诊

患者可手动输入病情，也可上传病历照片提取文字，之后获得就诊方向、候选医生、诊室建议和路线。

### 图片识别与人工核对

1. 选择 PNG、JPG 或 WebP 图片，原图上限 5 MB。
2. 前端处理图片尺寸与压缩内容；发送前的图片上限为 3 MB。此时尚未自动调用模型。
3. 点击“识别病历”，发送图片进行文字识别；识别结果填入病情输入框，并列出不确定内容。
4. 核对日期、医学术语、检查数值及遗漏信息，必要时手动修正，再勾选“我已核对并修正识别文字”。
5. 点击“推荐医生与诊室”。识别文字超过 5000 字时，先精简为可用病情摘要。

识别结果不是确认过的病历，也不证明影像、检验结果或诊断解释正确。请在上传前去除姓名、证件号、电话等身份信息。应用不将图片写入磁盘或日志，外部服务商的数据处理范围需按其约定单独确认。

### 医生、出诊时间与问答

候选来自现有有照片医生库，显示医生简介、匹配参考和就诊方向。详情页直接展示共用近 7 日工作时间表，再通过“查看就诊路线”了解下一步位置指引。

就诊问答围绕当前病情、所选医生公开资料和就诊准备展开。修改病情后开启新的问答上下文，避免把不同病例的对话混在一起。急症提示优先进入急诊/人工服务指引，不按普通门诊排班等待。

当前没有在线挂号、支付、叫号或预约确认。查看医生或路线不会创建转诊单或预约。

### 路线为预置示意

页面可选择“门诊大厅”或“综合服务台”作为起点，以流程图和步骤呈现电梯厅、门诊楼层、专科区域与分诊台的衔接。

楼层、诊室区域和到院路线均为预置示意，没有依据实时定位或院方地图计算，不应将其当作北京安贞医院安徽医院已经核实的真实空间路径。到院后须以院方当日标识、分诊人员和接诊安排为准。

## 5. 三模块共用医生工作时间

`shared-ui.mjs` 调用 `matching.mjs` 的排班生成逻辑，直接展示近 7 日、上午/下午的虚拟工作时间。医生详情中无需展开额外说明才能看见时间表。

同一医生在上转与导诊中使用同一生成规则，下转协作医生同样使用该组件。表中的“可登记意向”“需联系确认”是界面上的协调参考，不是真实余号、不验证医生在岗，也不表示挂号已成功。

上转择期申请仍有日期与时段选择；共用只读工作时间表用于先查看医生上班时间。下转按服务计划填写接收日期，导诊据时间表了解出诊意向，二者不会据此预约号源。

## 6. 数据和接入范围

| 项目 | 当前实现 | 尚未接入 |
| --- | --- | --- |
| 医生资料 | 安贞既有公开资料与照片；下转虚构协作团队 | 实时院方人员与能力目录 |
| 排班 | 本地生成近 7 日时间表 | 院方真实排班、挂号号源 |
| 上转 | 服务器共享申请和协调登记 | 院方申请、接收回执、转运接口 |
| 下转 | 共享服务计划、接收安排、双视图同步 | 跨医院账号、医嘱与床位系统 |
| 监测 | 预置序列、人工录入、趋势与时间线 | 医疗设备数据和真实连续采集 |
| 紧急情况 | 页面告警、AI 整理、人工处理记录 | 短信/电话/推送与院方消息回执 |
| 导诊 | 图像文字识别、问答、医生方向 | 正式病历归档与诊疗决策接口 |
| 路线 | 预设楼层与区域示意 | 实景院区地图、定位和导航 |
| 账户与数据 | 单个应用服务、服务器持久保存、跨浏览器同步 | 生产身份认证、医院权限、院方数据平台和完整审计 |

旧版上转存储键为 `anzhen-referral-demo-v1`，下转为 `anzhen-downward-workspace-v1`，仅为兼容历史记录保留，不作为产品界面文案。首次使用共享服务时，当前来源的旧记录会一次性合并到服务器，成功后保留原数据但不重复导入。浏览器无法读取其他网址的旧记录，本地历史转到云端需单独迁移并核对。迁移后更换浏览器或设备，只要访问同一服务即可查看共享记录；发布包不携带服务器业务数据或私有配置。独立离线 HTML 仍只在本浏览器保存，不自动联网同步。

导诊图片、病情和对话位于页面内存，刷新可能清除。角色切换不是身份认证，当前应用不适合作为已经具备生产权限与隐私保护体系的临床系统。

## 7. 当前验收证据

截至 2026-09-20 本次文档更新，页面实际操作已确认下转申请创建、下级接收登记、查看医生七日排班，以及监测突发事件触发真实 AI 整理成功。导诊已完成真实病历图片识别、人工核对、推荐医生、查看七日工作时间、诊室路线和围绕当前医生的问答。

异常重试、状态持久化及其他回归结果以 [验证记录](verification.md) 或对应验收报告为准。不能由已完成的链路或单次模型生成推断所有病例、模型场景或临床流程均已验证。

本地自动测试覆盖输入、模型输出结构校验与记录处理等技术行为，不能替代临床质量验证、真实院方联调或生产运行验收。
