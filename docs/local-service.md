# 本地后台服务说明

macOS 的 `启动工作台.command` 会将工作台安装为当前用户的 launchd 后台服务。默认网址保持为 **http://127.0.0.1:4173/**，成功启动后可以关闭终端；后台进程退出时由系统重新启动，并配置为该用户登录后自动启动。

这是本机服务。电脑睡眠、关机或用户退出登录期间不可访问，不用于向其他设备提供服务。登录自动启动属于已设置的服务行为，本文不代表已完成重登录、重启电脑或睡眠唤醒验收；实际检查范围以验证记录为准。

## 首次启动与日常使用

1. 安装 Node.js 22 或以上版本，保留完整项目文件夹。
2. 在原项目 `.env` 中保存服务配置。如文件缺失，可先运行 `node scripts/setup.mjs` 创建空白配置；该命令不覆盖已有文件。
3. 关闭此前手动运行工作台的进程，避免占用 4173 端口。
4. 双击 `启动工作台.command`。脚本安装运行副本、启动服务并尝试打开浏览器。
5. 看到后台服务启动成功后，可关闭启动时出现的终端窗口。以后直接打开本地网址即可。

若默认浏览器无法自动打开，手动访问上述网址即可，不影响已经启动的服务。安装程序不会停止占用目标端口的其他程序。

## 更新代码或配置

后台服务使用单独的运行副本，修改下载目录中的原项目文件不会立即影响它。应在**原项目**中编辑 `.env` 或代码，再双击 `启动工作台.command`，或在原项目目录运行：

```sh
npm run service:restart
```

该操作会重新复制原项目的运行文件和 `.env`，再重启后台服务。等待正在进行的匹配或问答完成后再更新，避免中断本次请求。浏览器刷新只会重新读取当前运行版本，不会同步原项目文件。

更新会先准备独立版本目录；新版本未能正常启动时，脚本尝试恢复之前的服务配置和版本。不要直接修改运行副本，否则下一次同步可能覆盖这些修改。

原项目移动或暂时不可用，不影响已安装的运行副本继续工作；后续管理和更新仍需使用完整项目中的管理脚本及可用的 Node.js。

## 管理命令

以下命令均在原项目目录执行，仅适用于 macOS：

| 操作 | 命令 | 结果 |
| --- | --- | --- |
| 安装、更新或恢复启动 | `npm run service:install` | 同步原项目，启用自动启动并启动服务 |
| 查看状态 | `npm run service:status` | 显示安装状态、管理状态、进程、健康状态、配置状态及日志目录 |
| 同步并重启 | `npm run service:restart` | 用原项目当前文件和配置更新运行副本 |
| 停止并暂停自动启动 | `npm run service:stop` | 停止服务；退出进程或下次登录均不会自行恢复，直到再次安装或启动 |

再次双击 `启动工作台.command` 或运行 `service:install` / `service:restart`，可恢复被暂停的服务。停止、重启和更新后台服务不主动删除浏览器内的转诊记录。

状态含义：

- `managed: true`：当前用户的服务已加载到 launchd。
- `healthy: true`：本地健康端点返回了正确服务标识；不代表已连接医院系统或已验证模型接口。
- `configured: true`：后台进程已加载非空 Key；不代表 Key 有效、账户有额度或拥有模型权限。
- `pid`：当前后台进程编号；自动重启后可能改变。

`GET /api/health` 只返回服务标识与本地运行状态，不读取上游结果、不调用模型、不产生生成费用。状态查询同样不产生模型生成请求。

## 安装目录与日志

这些路径中的 `~` 代表当前用户的主目录：

| 内容 | 位置 |
| --- | --- |
| 运行副本和版本记录 | `~/Library/Application Support/AnzhenReferralWorkspace/` |
| 当前版本入口 | `~/Library/Application Support/AnzhenReferralWorkspace/current` |
| 用户后台服务配置 | `~/Library/LaunchAgents/cn.anzhen.referral-workspace.plist` |
| 启动与错误日志 | `~/Library/Logs/AnzhenReferralWorkspace/` |

后台服务从版本目录的真实路径启动，`current` 指向当前安装版本。配置文件随运行副本复制到该目录，后台进程只在启动时加载它；Key 不写入后台服务 plist、服务状态输出或浏览器响应。运行目录和日志目录限制为当前用户访问，运行副本 `.env` 的文件权限为 0600。

日志为 `server.log` 和 `server-error.log`。反馈问题时提供错误信息即可，无需提供 `.env` 内容。

## 常见情况

- **网址打不开**：先确认电脑已唤醒且当前用户已登录，运行 `npm run service:status`。若服务未启动，重新双击启动脚本；仍失败时查看错误日志。
- **更新后仍显示旧内容**：确认修改的是原项目，并已重新运行启动脚本或 `service:restart`，然后刷新页面。
- **提示端口占用**：关闭此前前台启动的工作台，或确认占用该端口的是哪个程序。后台管理脚本不会终止其他程序。
- **停止后无法自动恢复**：这是 `service:stop` 的预期行为；重新运行启动脚本即可同时恢复服务和自动启动配置。
- **管理操作正在执行**：等待当前安装、更新或停止操作完成后再重试。
- **页面能打开，但智能匹配报错**：本地服务与上游模型是两条独立检查链。按页面提示检查原项目配置、网络、权限或额度；修改配置后重新同步。

建议保留 `PORT=4173`，并继续使用同一浏览器与 `127.0.0.1` 地址。浏览器本地存储按网址来源区分，改端口、改用 `localhost` 或更换浏览器都可能使原有转诊记录不在当前页面显示。

## Windows 与前台启动

Windows 的 `启动工作台.bat`，以及任意系统的 `npm start`，仍在前台运行，必须保留启动窗口；它们不安装上述 macOS 后台服务。关闭窗口或结束进程后，本地网址将不可用。

若要在 macOS 从后台方式切回前台调试，先运行 `npm run service:stop`，再运行 `npm start`，避免两个进程竞争同一端口。前台方式修改 `.env` 后，停止并重新运行 `npm start` 即可。
