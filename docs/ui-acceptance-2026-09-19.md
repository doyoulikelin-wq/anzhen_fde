## 完整业务流程

每条完整流程均经过：填写或选择病例 → 点击匹配 → 查看医生照片、简介、评分及理由 → 打开详情 → 选择意向安排（急症直接对接）→ 勾选复核并确认转诊 → 进入接收中心 → 填写协调地点、复核并保存 → 查看转诊记录。

## 修复与验证范围

1. 模型不再自由摘写医生资料，改为选择所选医生的原文条目引用；服务端解析后继续严格校验。保留医生身份、技术证据、分项分数等限制。
2. 重复申请判断加入来源医院与发起医生，避免不同来源申请被误合并。
3. 保存前合并最新记录，采用唯一单号及可用的浏览器写入锁，跨页同步状态；写入失败时保留表单并提示失败。
4. 长单号在记录与详情中换行。问答默认普通中文段落或编号清单。

最新自动测试 63 项通过，包含引用解析与记录存储回归。本轮真实生成请求共 7 次：5 次匹配（修复前 2 次未通过应用引用校验，3 次成功）、2 次问答（成功）。详情、保存、接收协调、重复提交及刷新不额外调用模型。没有进行额外批量付费压测。

本轮页面验收覆盖两个标签页交叉操作；同时写入竞争及写入失败等存储边界另由自动测试覆盖，不将它们描述为已在真实 UI 中注入验证。有限病例测试不构成临床质量验证、并发容量认证或院方系统联调。
