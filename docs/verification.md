## 本地服务常驻与自动恢复（2026-09-20）

处理前 `127.0.0.1:4173` 无监听、HTTP 无法连接；原启动方式为临时前台进程。现安装当前用户的 macOS LaunchAgent，保持原网址与仅本机访问；运行文件位于用户 Application Support 的独立版本目录，密钥仅复制到权限为 0600 的本地配置文件。启用登录自动加载、退出自动重启与 5 秒重启节流。更新失败保留回滚路径，双击启动脚本会同步原项目的代码与配置。

实际验收：

- 后台进程由 launchd 管理（父进程为 1），启动命令完成退出后服务仍可访问。
- 发送 SIGTERM 后更换 PID 并恢复健康，实测约 **0.4 秒**；发送 SIGKILL 后再次更换 PID 并恢复健康，实测约 **5.3 秒**。
- 两个重启命令交叠时，第二个被管理锁拦截；第一个正常更新，运行版本目录与状态元数据一致。
- 首页、54 张医生照片、健康端点和配置加载正常；`.env` 与后端源码仍返回 404，端口仍仅监听 `127.0.0.1`。
- 用户原浏览器刷新后，4 条转诊记录及状态均保留。
- 自动测试 **64 项通过**，新增健康检查不调用上游、不泄露配置、沿用 Host/Origin 限制；启动脚本和系统服务配置语法通过。

本轮没有付费模型调用。登录自启已配置；未实际执行注销、重启电脑或睡眠/唤醒测试，不将其描述为实测通过。睡眠、关机期间本机网址不可用，外部模型服务可用性也不由本地进程重启保证。操作说明见 [后台服务说明](local-service.md)。原始恢复计时记录保存在 `qa/local-service-report.json`，不进入交付包。

## 发现并修正

1. 首轮问答曾把虚拟余号误列为评分因素：匹配与问答现在共用明确评分规则，并禁止学历、职称、虚拟排班参与评分。
2. 曾把一般心律失常评估过度解释为消融能力，且提示词单独约束仍未守住技术分上限：增加服务端证据限制，缺明确技术证据者技术项最多 10 分，只有门诊归属且无详细专长者为 0 分；替换越界理由，重算总分并排序。
3. 删除从“特需门诊”推断安排便利性的匹配理由。补充否定和历史病例回归，避免把“术后随访，不评估再次消融”当作当前消融需求。

保存响应的独立离线回放 **5 组通过**，逐位检查全部 8 位候选；无消融证据者技术 24→10、总分 82→68，有明确证据的其余 7 位分值保持不变。最终真实页面调用再次验证技术上限、分项加总、照片和详情显示。原中间测试的人工复核失败已记录，未将其误列为质量通过。
